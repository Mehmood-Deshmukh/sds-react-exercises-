      Page skeleton

      • Components
      • JSX
      • import / export

      Cut the page into boxes. You'll make a Header and a Footer component and snap them into App. Every later build goes in the space between them. Notes: sections 3 and 4.

      Steps

      1. Make a components folder

        Inside src, create a folder called components. Every component you build goes in here, one file each.

      2. Build the Header

        A component is a function that returns JSX. Its name starts with a capital letter, and export default lets other files import it. In JSX you write className where HTML uses class.

      3. Build the Footer

        Put your own name in. Anything inside { } in JSX is plain JavaScript, so {year} shows the current year. It's worked out once, outside the component, because it doesn't change while the page is open.

      4. Snap them into App

        Once a component is imported, you use it like a custom HTML tag: <Header />.

      5. Check the browser

        You should see the header at the top and the footer at the bottom, like the finished model. From now on, each build goes inside <main>.

      Try breaking it

      Do each one, look at what happens, then undo it.

      • In App.jsx, write <header /> instead of <Header />. Your title disappears: lowercase names are treated as plain HTML tags.
      • In Header.jsx, change className to class. Open the Console (F12) and read React's warning.
      • Delete the <header> wrapper so the component returns an <h1> and a <p> side by side. JSX must return one parent element. An empty fragment, <>…</>, fixes it without adding an extra tag.

      Level up

      Make a Notice component that shows "🚧 Work in progress" inside a <div className="card">, and put it in <main> twice. One component, two copies.

      Stuck?

      1. Does each component file end with export default ComponentName;?

      2. Import paths start from the file you're in. From App.jsx it's ./components/Header, with no .jsx needed.

      3. Blank page? Open the Console (F12). The red error usually names the file and the line.

      Class API

      Every endpoint answers GET requests with JSON, so you can open any of them in the browser. Lists come back as plain arrays; single things come back as objects. Open one and press Send request to see the answer.

      Slow it down: ?delay=2000

      Add it to any address and the API waits that many milliseconds (up to 5000) before answering. Perfect for checking your loading messages.

      Make it fail: ?fail=true

      Add it to any address to get a 500 error with an error message. Use it to test what your app shows when things go wrong.

      When something breaks

      First, open DevTools (F12) and read the first red message in the Console. Then find it below.

      "Failed to fetch", or a CORS error

      The browser couldn't reach the API. Check API_URL in src/api.js: it should match the address at the top of this page exactly, with no slash at the end. If the dot next to it is red, the API itself is down, so tell your instructor.

      If the API is on a free host, it may fall asleep when nobody uses it. The first request can then take up to a minute; after that it's quick.

      Cannot read properties of null (reading '…')

      You're reading from data that hasn't arrived yet. On the first render your state is still null. Return a loading message while it's null, as in Build 4.

      Objects are not valid as a React child

      You put a whole object in JSX, like {joke}. React can show text and numbers, not objects. Show a field instead: {joke.setup}.

      Each child in a list should have a unique "key" prop

      Every element you return from .map() needs key={something unique}, usually an id from the data.

      Too many re-renders

      You're calling a setter while drawing, often onClick={setLikes(likes + 1)}. Wrap it in a function: onClick={() => setLikes(likes + 1)}.

      I changed a variable but the screen didn't update

      Only state changes made through a setter make React redraw. For arrays and objects, hand the setter a new copy instead of changing the old one (Build 7).

      My effect runs over and over

      Check the dependency list. No list means "after every render". If the effect sets a piece of state that's also in its list, it triggers itself.

      Every request shows up twice in the Network tab

      That's React's development mode running effects twice on purpose, to catch missing cleanups. It's normal, and it doesn't happen in a built app.

      The page is blank and there's no error

      Check that the terminal running npm run dev is still open, that you're on the address it printed, and that App.jsx ends with export default App;.
